## Bug：捕获后进出 NPC 战斗残留异常

**状态：未解决（可稳定复现）**

### 现象描述

在遭遇页丢球捕获（尤其自动捕捉 + 必中的大师球）后，立刻进入 NPC 对战再退出，会产生以下异常：

1. **仓库中出现"已逃走"的宝可梦** — 宝可梦确实被抓进了仓库，但仓库里显示"精灵逃走了"（`pokedex.js` 中遭遇日志描述按 `result: 'fled'` 渲染）。
2. **图鉴中产生多条遭遇日志** — 同一次遭遇被记录成多条日志（捕获 `caught` 与逃跑 `fled` 并存，矛盾），图鉴 `seen` 计数也被多次累加。
3. **界面残留** — 返回遭遇页时精灵 UI 消失、残留捕获成功文案框、点击后底部 tile 不滚动、导航页误显「正在与宝可梦对战，移动暂停」。

### 复现步骤

1. 开启自动捕捉（智能选球，如大师球必中）。
2. 在遭遇页丢球捕获后立即切到 NPC 对战。
3. 反复进出 NPC 对战（或直接退出战斗回遭遇页）。
4. 查看仓库与图鉴：出现"精灵逃走了"的已捕获个体，图鉴里该宝可梦的遭遇日志有捕获 + 逃跑多条。

### 日志证据（用户提供）

- 不断进出 NPC 对战时，系统日志一直刷「宝可梦逃跑」类记录。
- 最终该宝可梦被捕获入仓库，但仓库条目显示"精灵逃走了"。

### 已尝试的修复（均未奏效）

1. `throwBall` 捕获成功分支追加 `if (_bgCatch || _autoCatching)` 统一收尾（`goIdle`）。
2. `autoCatch()` 入口加 `phase === 'caught' || phase === 'fled'` 守卫，防止已落库遭遇被重复捕捉。
3. `fleeEncounter()` 加 `phase === 'caught'` 守卫，防止捕获后又被标记逃跑。

### 当前分析（根因未定位）

后台结算链路复杂，存在多处疑点：

- `startNpcBattle` 中 `setPhase('battle')` 为同步，而 `handoffEncounterToBackground` 经 `import().then()` **异步**调用，`_bgCatch` 置位时机可能与 `throwBall` 的判定/快照分支产生竞态。
- `handoffEncounterToBackground` 对 `prevPhase === 'encounter'` 的路径会启动 `autoCatch()` 后台继续丢球；若遭遇**已被捕获落库**但仍以 `'encounter'` 相位交接（例如 `resumeBgEncounter()` 把已捕获遭遇恢复成 `phase = 'encounter'` 后再进战斗），会对同一遭遇二次丢球 → 第二次判定才产生 `fled` → 追加矛盾日志。
- `replayBgResult()` 补播时会把已落库的捕获遭遇**重建为活跃遭遇**（`setPhase('encounter')` + `setCurrentEncounter`），期间再次进战斗会被当作新一轮遭遇处理。
- 涉及模块：`battle.js`（throwBall / autoCatch / handoffEncounterToBackground / resumeBgEncounter / replayBgResult / cleanupEncounterState / goIdle）、`battle-view.js`（startNpcBattle / finishBattle）、`ui.js`（showView 切回游戏页触发补播）。

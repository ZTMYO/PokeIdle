## 1. DPI 补偿在不同设备上效果不一致（其他玩家 UI 偏小）

**现象**：开发机（DPR=1.75, scale=2）上窗口内布局正常，但其他玩家的设备上运行最新版本时 UI 明显偏小。

**现状（已回退）**：
- 原方案：Rust `set_window_scale` 用物理像素设窗口（320×scale）+ `window.set_zoom(scale/DPR)` 抵消系统缩放，期望 CSS 视口恒为 320×400。
- 失败根因：`set_zoom` 在不同 WebView2 版本/系统上生效行为不一致 → 部分玩家 CSS 视口比基准大，1 CSS px 对应物理像素更少 → UI 偏小。

**尝试过的替代方案（均失败，已回退）**：
1. 前端测量 + CSS `zoom` 二次补偿 → 用理论基准 320×400 会改掉开发机原效果。
2. `transform: scale` 固定 layout 尺寸 → transform 不参与 flex 布局，`screen-wrapper` 被压扁。
3. CSS zoom + 冷静期/偏差阈值 → 刷新时序不稳，布局被扰动。
4. CSS zoom + 永久禁用机制 → splash 阶段测量后永久禁用补偿，进入游戏后视口变化无法再补，UI 缩小。
5. 最终版：Rust 只设窗口 + 返回 `suggested_css_zoom=effective/DPR`，前端直接 `documentElement.style.zoom` → 窗口显示正常，但产生连锁副作用：tooltip、丢球动画等所有依赖鼠标坐标/`getBoundingClientRect` 的定位全部偏移（CSS zoom 下渲染坐标与布局坐标不一致），且 splash→游戏阶段布局变化仍不稳定。**方案整体行不通，代码已全部回退。**

**遗留问题**：
- 如何在保证各设备 UI 一致的前提下处理 DPI，尚无可行方案（`set_zoom` 兼容性不可控，CSS zoom 破坏坐标体系）。
- 回退后其他玩家设备上 UI 偏小的问题依旧存在。

**涉及文件**：`src-tauri/src/window_manager.rs`、`src/views.js`、`src/ui.js`（均已回退至 git HEAD）。

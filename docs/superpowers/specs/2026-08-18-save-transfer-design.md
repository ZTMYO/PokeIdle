# 跨平台存档导入导出设计

## 1. 目标

完善 PokeIdle 的存档导入导出能力，使 Android 与桌面版能够通过 JSON 文件双向迁移存档，并在覆盖前提供摘要确认、自动备份和一次手动恢复能力。

成功标准：

- Android 可以从系统文件选择器导入桌面版存档。
- Android 可以通过系统分享面板导出存档到文件、网盘或其他设备。
- 桌面版可以导入 Android 导出的存档，原有 Tauri 文件选择体验保持可用。
- 导入前必须显示当前存档与待导入存档的摘要，只有用户确认后才覆盖。
- 导入前必须成功保存一份当前存档备份；备份失败时禁止覆盖。
- 用户可以在设置页恢复最近一份导入前备份。
- 旧版原始 JSON 存档继续可用。

## 2. 非目标

- 不实现账号系统、云存档或自动跨设备同步。
- 不实现多槽位存档管理。
- 不保留多份历史备份，只保留最近一份导入前备份。
- 不引入压缩、加密或自定义二进制存档格式。
- 不改变游戏运行时存档结构和现有字段迁移逻辑。

## 3. 现状

桌面版设置页已有导入和导出按钮，通过 Tauri 命令打开原生文件选择器。Android 设置页沿用相同按钮，但目前只显示「仅桌面版」。

现有导出逻辑会把 `stats.lastSaveTime` 人为增加 10 年，避免导入后被旧候选覆盖。这个做法会修改运行中的 `gameData`，并产生不真实的保存时间。新设计取消该行为，改为在用户确认导入后统一调整导入存档的时间戳。

Android 已使用 Capacitor Filesystem 保存 `save.json` 和 `save.json.bak`，桌面版使用 Tauri 应用数据目录，同时保留 `localStorage` 兜底。

## 4. 方案选择

采用共享存档逻辑与平台文件适配相结合的方案：

- 共享 JavaScript 模块负责序列化、解析、格式校验、摘要生成、文件名和导入时间戳。
- Android bridge 负责系统分享、私有备份文件和备份读取。
- Tauri 命令负责桌面文件选择、私有备份文件和备份读取。
- 浏览器环境使用文件输入和 Blob 下载作为回退。

该方案把影响数据安全的规则集中在可单元测试的模块中，同时保留各平台可靠的原生文件交互。

## 5. 存档文件格式

导出文件继续使用原始游戏数据作为 JSON 顶层对象，并增加可选元数据字段：

```json
{
  "items": {},
  "stats": {
    "lastSaveTime": 1787040000000
  },
  "__pokeidleMeta": {
    "formatVersion": 1,
    "appVersion": "1.0.8",
    "exportedAt": 1787040000000
  }
}
```

兼容规则：

- 没有 `__pokeidleMeta` 的旧存档按格式版本 0 处理并允许导入。
- 当前应用支持 `formatVersion` 0 和 1。
- 高于当前支持版本的文件拒绝导入，并提示使用更新版本的应用。
- 未知的游戏数据字段原样保留，避免丢失后续版本可识别的数据。
- 导入完成后移除文件级 `__pokeidleMeta`，不把导出元数据写入运行时存档。
- 导出过程使用深拷贝，不修改运行中的 `gameData` 或 `lastSaveTime`。

导出文件名使用 `pokeidle-save-YYYYMMDD-HHmmss.json`。

## 6. 组件职责

### 6.1 共享存档传输模块

新增无 DOM 的 JavaScript 模块，提供以下职责：

- 将当前游戏数据序列化为带元数据的导出 JSON。
- 解析 JSON，并区分旧格式、当前格式和未来格式。
- 校验顶层对象及 `items`、`stats` 等必需结构。
- 生成文件名和用户确认所需的存档摘要。
- 在不改变原始对象的前提下生成可导入的数据副本。
- 将导入存档的 `lastSaveTime` 调整为大于当前存档和当前时间的值。

摘要包括：

- 保存时间：`stats.lastSaveTime`。
- 主角角色：`settings.gender`。
- 糖果数量：`items.candy`。
- 队伍中的宝可梦数量：`team.length`。
- 仓库中的宝可梦数量：`roster.length`。
- 图鉴数量：`Object.keys(pokedex).length`。

缺失的非核心摘要字段显示为「未知」，不因此拒绝旧存档。

### 6.2 设置页控制器

设置页负责操作状态和用户确认，不自行实现格式规则：

- 导出前调用 `saveGame()`，确保快照包含当前进度。
- 导入文件解析成功后显示当前存档与待导入存档摘要。
- 用户确认后按「备份、覆盖、刷新」顺序执行。
- 恢复操作显示备份摘要并要求二次确认。
- 操作期间禁用相关按钮，防止重复点击和并发覆盖。

### 6.3 平台适配层

平台适配层使用统一语义：

- `exportSaveData(data, fileName)`：导出或分享文件。
- `createImportBackup(data)`：写入最近一份导入前备份。
- `loadImportBackup()`：读取导入前备份，没有备份时返回空值。

读取待导入文件由设置页按平台选择：

- Tauri 调用现有原生文件选择命令。
- Android 和浏览器使用隐藏的 `<input type="file" accept="application/json,.json">`，由系统文件选择器返回内容。

## 7. 平台行为

### 7.1 Android

- 新增 Capacitor Share 插件。
- 导出时把 JSON 临时写入 `Directory.Cache`，获取文件 URI 后打开系统分享面板。
- 分享面板关闭后清理临时文件；清理失败不影响已完成的导出。
- 导入前备份写入应用私有数据目录的 `save.import-backup.json`。
- 读取备份失败时区分「不存在」与「读取错误」。
- 不申请公共存储权限。

### 7.2 桌面版

- 保留 Tauri 原生文件选择器。
- 导出对话框允许用户选择保存位置，并使用建议文件名。
- 导入前备份写入 Tauri 应用数据目录的 `save.import-backup.json`。
- 增加读取该备份的 Tauri 命令。

### 7.3 浏览器回退

- 导入使用隐藏文件输入。
- 导出使用 Blob URL 和临时下载链接。
- 导入前备份存入独立的 `localStorage` 键。
- 浏览器回退不承诺跨浏览器迁移，但不得影响桌面和 Android 主流程。

## 8. 导出流程

1. 用户点击「导出」。
2. 禁用导入、导出和恢复按钮，并显示「导出中」。
3. 调用 `saveGame()` 更新当前真实保存时间。
4. 对当前存档创建深拷贝，加入格式元数据并序列化。
5. 调用平台导出接口。
6. 成功时显示「已导出」并记录系统日志；用户取消时恢复按钮状态，不记录失败。
7. 发生其他错误时显示可理解的失败提示，并保留当前存档。

## 9. 导入流程

1. 用户点击「导入」，系统打开 JSON 文件选择器。
2. 取消选择时直接返回，不显示错误。
3. 读取 UTF-8 文本，并在解析前执行文件大小上限检查；超过 20 MB 的文件拒绝导入。
4. 共享模块解析、验证并生成摘要。
5. 设置页显示当前存档与待导入存档的对比确认层。
6. 用户取消时不修改任何数据。
7. 用户确认后先调用 `saveGame()`，再把当前存档写入导入前备份。
8. 备份成功后生成导入副本，移除文件元数据并调整 `lastSaveTime`。
9. 使用 `setGameData()`、现有兼容初始化和 `saveGame()` 写入主存档及各兜底来源。
10. 保存成功后记录系统日志，提示成功并刷新游戏。

如果备份或保存失败，导入流程停止并恢复内存中的原存档。未成功写入完整新存档时不得刷新。

## 10. 恢复流程

1. 设置页加载时检查是否存在导入前备份。
2. 没有备份时隐藏或禁用「恢复导入前存档」。
3. 用户点击恢复后解析备份并显示摘要。
4. 用户二次确认后调整备份存档时间戳，覆盖主存档并刷新。
5. 恢复操作不创建新的导入前备份，也不删除现有备份。
6. 下一次成功确认导入时，旧备份被新的导入前存档替换。

## 11. 设置页交互

「角色与存档」区域保留现有紧凑布局，提供：

- 导出存档。
- 导入存档。
- 恢复导入前存档。
- 重置存档。
- 刷新游戏。

导入和恢复使用同一个紧凑确认层。确认层显示来源文件名（导入时）、存档摘要、取消按钮和明确的覆盖命令按钮。重置存档继续使用现有二次点击确认。

按钮状态包括：默认、处理中、成功和失败。处理中时同组的数据操作按钮不可点击，状态变化不得改变设置页整体尺寸。

## 12. 错误处理

| 场景 | 行为 |
|---|---|
| 用户取消选择或分享 | 静默恢复按钮状态 |
| 文件超过 20 MB | 提示文件超出 20 MB 的存档大小限制 |
| JSON 损坏 | 提示文件不是有效存档 |
| 缺少核心字段 | 提示存档格式不完整 |
| 格式版本过新 | 提示升级应用后再导入 |
| 导入前备份失败 | 中止导入，当前存档不变 |
| 主存档写入失败 | 恢复内存原存档，保留备份并提示失败 |
| 分享临时文件清理失败 | 记录警告，不把成功导出改为失败 |
| 备份文件损坏 | 禁止恢复并提示备份不可用 |

错误信息不展示本机绝对路径、堆栈或存档正文。详细异常只写入开发控制台。

## 13. 测试策略

### 13.1 自动化测试

共享模块使用 Node 内置测试运行器覆盖：

- 旧版无元数据存档可导入。
- 当前格式存档可导入，元数据会被移除。
- 损坏 JSON、数组、缺少核心字段和未来版本会被拒绝。
- 摘要对完整存档和缺失可选字段的旧存档均稳定。
- 导出文件名使用本地时间并保持合法字符。
- 导出序列化不修改原始对象和真实 `lastSaveTime`。
- 导入副本的时间戳严格大于当前存档和当前时间。

Android bridge 测试或静态契约检查覆盖：

- Capacitor Share 插件已接入。
- 导入前备份使用独立文件名。
- 分享临时文件位于缓存目录，不写入公共存储。

现有 `npm run test:mobile` 必须全部通过。

### 13.2 手工验收

- Android 导出后可通过系统分享面板保存到文件或发送到桌面。
- 桌面可以导入 Android 文件，摘要正确，确认后恢复进度。
- 桌面导出文件可在 Android 系统文件选择器中选择并导入。
- 取消选择、取消确认和取消分享均不修改存档。
- 导入后强制结束应用再启动，仍加载导入存档。
- 恢复导入前存档后，强制结束并重启仍加载恢复存档。
- 损坏、缺字段和未来格式文件均不会覆盖当前存档。
- Android 8.0 及以上版本不需要公共存储权限。

## 14. 发布影响

- 新增 Capacitor Share 运行时依赖，并重新同步 Android 工程。
- Android APK 需要重新构建和签名。
- 本次变更不修改包名、签名密钥或最低 Android 版本。
- 发布说明应注明桌面与 Android 存档可通过 JSON 文件双向迁移，并提醒导入会覆盖当前进度。

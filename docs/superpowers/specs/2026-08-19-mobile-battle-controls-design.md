# 手机对战操作区布局修复设计

## 目标

修复 Android 手机模式下 NPC 对战操作区的两种布局异常：

- 初始操作态的「攻击」「替换」「自动」按钮互相重叠。
- 选招态的 2 × 2 技能按钮超出游戏画面。

修复后，两种状态的全部按钮都应位于掌机画面内，并保持适合手机触控的尺寸。

## 非目标

- 不修改战斗规则、自动战斗、换人或技能选择逻辑。
- 不调整战斗操作区的 DOM 结构和按钮文案。
- 不改变桌面端布局。
- 不重做战斗界面的整体视觉设计。

## 现状与根因

手机模式通过全局规则为按钮设置 `34px` 的最小高度，以保证触控体验。NPC 对战底部操作区 `.b-bottom` 仍固定为 `56px`，但操作态和选招态都需要容纳两行按钮。

两行按钮至少需要 `34px + 34px`，再加上行间距和容器内边距，实际所需高度大于 `56px`。浏览器因此把按钮撑出固定底栏：操作态表现为按钮重叠，选招态表现为技能区域超出画面。

## 方案

仅在 `html.mobile-mode` 下把 `.b-bottom` 高度调整为 `92px`：

- 保留移动端按钮 `34px` 的最小触控高度。
- 继续使用现有 2 × 2 技能网格和右侧两行操作布局。
- 由现有纵向 Flex 布局压缩上方战斗场景的可用高度，保证整个界面仍在掌机视口内。
- 桌面端 `.b-bottom` 继续使用 `56px`，避免改变现有桌面视觉比例。

不为战斗按钮单独取消全局最小高度。这样可以直接消除高度约束冲突，同时保留手机上的可点击面积。

## 布局约束

- 手机底栏高度固定为 `92px`。
- 两行 `34px` 按钮、行间距、上下内边距以及 NPC 信息行必须能完整容纳在底栏中。
- `.b-left`、`.b-right`、`.b-cmd` 和 `.b-actions` 继续使用现有 Flex/Grid 收缩规则，不增加固定宽度。
- 技能名继续使用省略号处理过长文本，不能横向撑开网格。
- 自动战斗遮罩继续以 `.b-bottom` 为定位基准并覆盖完整底栏。

## 测试策略

新增移动端战斗布局契约测试，验证：

1. 基础 `.b-bottom` 高度仍为 `56px`，桌面端行为不变。
2. `html.mobile-mode .b-bottom` 存在 `92px` 的覆盖规则。
3. 手机底栏高度足以容纳两行 `34px` 按钮、间距和 NPC 信息行。
4. 操作态和选招态继续使用现有两行布局选择器，防止后续修改重新引入溢出。

随后运行移动端测试、完整 Node.js 测试和 Web 资源构建。自动化验证通过后重新生成正式签名 APK，并在 Android 真机上进入 NPC 对战，分别检查操作态和选招态。

## 验收标准

- 「攻击」「替换」「自动」三个按钮互不覆盖，文字完整可见且可正常点击。
- 四个技能按钮全部位于掌机画面内，不超出底部边界。
- 返回按钮和技能详情仍可正常显示、点击。
- 上方宝可梦、血条和战斗动画没有重叠或裁切异常。
- 桌面端战斗底栏尺寸和操作方式保持不变。

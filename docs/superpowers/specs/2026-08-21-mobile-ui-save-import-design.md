# 手机主页与存档导入优化设计

## 目标

本次迭代处理四个相关问题：

1. 合并 upstream fork 的最新修复，并保留当前分支已有的道路坐标修复、存档传输修复和用户本地改动。
2. 优化手机主页应用区，解决当前 `6 列 × 3 行` 图标过于拥挤的问题。
3. 在不改变底部道具栏现有视觉尺寸和间距的前提下，增加手机触摸左右滑动换页。
4. 修复 Android 手机导入存档确认后无反应、重启后新存档也未生效的问题。

## 范围与非目标

### 范围

- `src/phone.js` 和 `src/styles.css` 的手机主页应用网格。
- `src/main.js` 和必要的背包样式/测试，用于道具栏触摸滑动。
- `src/save-transfer-controller.js`、`src/save-persistence.js`、`src/views.js` 及相关测试，用于导入事务和手机可见提示。
- upstream/main 的可审查合并提交。

### 非目标

- 不改变应用顺序、图标资源、红点规则和应用内部功能。
- 不改变底部道具栏的图标大小、槽位间距、栏高度、页码指示条或桌面滚轮行为。
- 不取消导入前备份，也不允许导入失败时留下半写入状态。
- 不绕过 Git 或外部安全审核服务；无法 fetch upstream 时不猜测远程内容。

## 现状与根因

### 手机主页拥挤

`src/phone.js` 将 18 个应用全部放在同一个 `.phone-page`；`src/styles.css` 使用：

```css
grid-template-columns: repeat(6, minmax(0, 1fr));
grid-template-rows: repeat(3, minmax(0, 1fr));
gap: 4px 2px;
```

在 Android 掌机固定画布缩放后，每列可用宽度较小，图标和名称之间几乎没有横向呼吸空间。设计确认采用 18 个应用同屏的 `5 列 × 4 行` 网格，并使用舒适间距。第 4 行只占用 3 个应用，其余轨道保留空白，确保排列稳定。

### 道具栏缺少触摸翻页

`src/main.js` 已实现 `wheel` 和页码点击翻页，但没有 `pointerdown/pointerup` 或触摸手势。Android 手指滑动不会触发 wheel，因此用户无法自然切换第二页道具。

### 导入确认后无反应

`src/views.js` 将导入成功/失败提示传给 `updateTextBox`，而 `updateTextBox` 在非挂机页和非孵蛋页直接返回；设置页因此看不到错误。

导入流程在 `replaceSaveWithBackup` 中先保存当前存档、写入导入前备份，再应用新存档并调用 `saveGame({ strict: true, preserveTimestamp: true })`。严格持久化会同时尝试 Tauri、localStorage 和 Android bridge；其中任一来源失败都会抛出 AggregateError，并回滚内存与持久化数据。Android 私有 Data 文件是手机重启后唯一可靠的主存档来源，非 Android 备用来源失败不应阻止 Android 导入。

## 设计方案

### 1. upstream 合并策略

在隔离 worktree 中执行 `git fetch upstream --prune`，读取 `HEAD..upstream/main` 的提交列表和差异后再合并。合并前记录当前工作区变更，不覆盖以下用户内容：

- `src/save-platform.js`
- `.superpowers/`
- 当前道路坐标修复和本次未提交的工作内容

如果 fetch 或合并被外部安全审核服务阻断，停止远程操作并向用户报告具体错误，不使用替代 URL 或间接命令规避审核。

### 2. 手机主页网格

保持 `APPS` 数组顺序和 18 个应用同屏渲染，只调整网格布局：

- 列数：5。
- 行数：4。
- 横向和纵向 `gap` 使用能在固定掌机画布内留下可点击空隙的舒适值。
- 应用单元格使用 `min-width: 0`，名称保持单行省略/不溢出。
- 图标尺寸不扩大，避免底部道具栏和时钟区域被挤压。
- 移动端使用该舒适网格；桌面端沿用同一应用结构，不新增第二套导航逻辑。

### 3. 道具栏触摸滑动

在现有 `#backpack` 翻页控制旁增加统一手势状态：

- `pointerdown` 记录起点、起始时间，并捕获指针。
- `pointerup` 计算 `dx/duration`；水平距离达到栏宽约四分之一或水平速度达到阈值时才切页。
- `Math.abs(dx) <= Math.abs(dy)` 时视为垂直滚动，不切页。
- 道具槽点击仍由现有 `.bag-slot` click 处理；短按不触发翻页。
- 使用 `touch-action: pan-y`，允许页面垂直滚动，同时保留水平换页。
- 保留现有 wheel 和页码点击逻辑。

### 4. Android 存档导入事务

将持久化能力拆分为“必需来源”和“尽力来源”：

- Android bridge 存在时，`mobile.saveGameData` 是导入成功的必需写入目标。
- Tauri 或浏览器 localStorage 属于备用来源；继续尝试写入，但单个备用来源失败只记录错误，不使 Android 导入失败。
- strict 模式仍用于普通桌面/跨来源一致性场景；导入控制器在 Android bridge 下使用移动端成功判定。
- Android 主存档写入失败时，必须恢复内存和已写入的可回滚来源，并返回稳定错误码。
- 导入前备份仍写入 Android 私有 Data 的独立备份文件。
- 成功后立即更新当前界面可见状态，并通过移动端安全 reload 入口重新初始化；reload 失败时不得丢失已写入的主存档。

### 5. 手机可见提示

在设置页提供独立的存档操作提示元素（toast/status）：

- 导入成功、取消、解析失败、备份失败、写入失败均有可见文案。
- 提示不依赖底部挂机文字框。
- 提示使用 `aria-live="polite"`，不阻塞确认按钮和返回键。
- 成功提示至少保留到 reload 开始；失败提示保留足够时间供用户阅读。

## 数据流

```text
选择文件
  -> 解析与校验
  -> 显示确认弹窗
  -> 保存当前存档
  -> 写入 Android 导入前备份
  -> 应用新存档到内存
  -> 写 Android 主存档（必需）
  -> 尝试备用来源（尽力）
  -> 更新提示
  -> 安全刷新；失败则保留已写入主存档并提示
```

任一步骤在应用新存档前失败，都不得修改当前存档。主存档写入失败时恢复原内存和持久化内容。

## 测试策略

### fork 合并

- fetch 成功时检查待合并提交列表、冲突文件和合并后的工作区差异。
- fetch 被审核服务拒绝时不产生 Git 状态变化，并在交付中报告阻塞。

### 手机主页

- 静态契约确认 `.phone-page` 使用 5 列、4 行和正向 gap。
- 确认 18 个 `APPS` 条目仍全部渲染。
- 确认应用顺序和红点节点不变。

### 道具栏

- pointer 手势的短按不切页。
- 水平滑动向左/向右分别切换相邻页面。
- 垂直滑动和斜向非水平手势不切页。
- wheel、页码点击和现有道具槽点击回归通过。

### 存档导入

- Android 主写入成功、备用 localStorage 失败时导入仍成功。
- Android 主写入失败时不应用新存档并恢复旧存档。
- 导入前备份失败时不应用新存档。
- 成功/失败提示写入设置页可见元素，而不是依赖 `textBox`。
- 导入成功后调用安全 reload；reload 调用前 Android 主存档已经完成写入。

## 验收标准

- 手机主页 18 个应用图标之间有明显可点击间隔，名称不重叠、不超出画布。
- 底部道具栏视觉效果与当前版本一致，手指左右滑动可以在两页之间切换。
- Android 选择存档并确认覆盖后，重启应用能看到新存档内容。
- 导入失败时手机设置页显示明确错误，当前存档不被破坏。
- 现有移动端测试和完整 Node 测试全部通过。

# Android 后台挂机与捕捉画面布局修复设计

## 1. 目标

本次更新面向 Android 端，完成两项相互独立但需要一起发布的能力：

- 应用退到后台后，继续自动遇敌、选择精灵球、判定捕获或逃跑，并保存结果。
- 修复战斗画面扔球后整个场景发生偏移、战斗结束后才恢复的问题。

成功标准：

- 用户开启后台挂机后，Android 通知栏显示常驻运行通知，并可通过通知停止后台挂机。
- 屏幕关闭或应用切到后台期间，自动遇敌和自动抓捕继续按游戏规则结算；返回前台后能看到最新存档和累计结果。
- 后台期间不要求播放音乐或逐帧渲染捕捉动画。
- 捕捉动画结束后，遭遇视图和动画舞台恢复到 CSS 布局；连续多次扔球、切换页面、旋转/调整系统安全区后，战斗场景不再整体偏移。
- 桌面端行为保持不变，现有存档格式和签名发布流程保持兼容。

## 2. 非目标

- 不把完整游戏引擎迁移到 Java/Kotlin。
- 不在后台播放音乐、显示战斗动画或保持屏幕常亮。
- 不新增账号、云存档、多设备同步或新的战斗规则。
- 不重做战斗页面视觉设计，不替换现有宝可梦和精灵球素材。

## 3. 现状与根因

### 3.1 后台运行

游戏主循环位于 `src/main.js`，依赖每秒一次的 `setInterval(onGameTick, 1000)`；Android WebView 进入后台后会被系统节流或暂停定时器。现有 Capacitor bridge 只在 `appStateChange` 和 `pause` 时保存数据，没有 Android 原生前台服务，也没有后台时间片结算入口。

战斗模块已经支持“遭遇被其他页面或 NPC 对战打断后后台自动捕捉”的即时落库分支，但该分支仍依赖 JavaScript 任务持续运行，不能覆盖应用真正退后台或进程被系统回收的情况。

### 3.2 战斗画面偏移

`src/animation.js` 的 `setupCatchAnim()` 为捕捉动画把 `#encounterView` 和 `#catchStage` 改为固定像素尺寸并设置 `position/left/top/width/height` 内联样式；`restoreCatchAnim()` 只恢复宝可梦和精灵球的样式，没有清除两个容器的内联布局。

Android 移动端的掌机高度由 `--mobile-layout-height` 动态计算，且 `getStageSize()` 会缓存第一次测得的尺寸。扔球后，后续遭遇继续使用旧的固定容器尺寸或旧舞台高度，导致整个战斗场景相对当前 WebView 坐标系偏移；离开战斗后页面重新布局，所以表现为“战斗结束恢复”。

## 4. 方案选择

采用“Android 前台服务 + JavaScript 时间戳结算 + 前台同步”的方案：

- 前台服务负责进程保活、常驻通知和定时触发同步；
- 游戏状态以后台开始时间和最后结算时间为依据，按经过时间批量执行可重放的挂机逻辑；
- 原有捕捉概率、精灵球消耗、图鉴、仓库、日志和存档函数继续作为唯一业务规则来源；
- 后台不调用 DOM 动画和音乐 API，避免 WebView 不可见时产生坐标或媒体状态问题；
- 回到前台时先完成未结算时间片，再刷新界面；若后台期间有遭遇结果，只展示汇总文案或最近结果，不重播已经错过的逐帧动画。

相比“仅保持 WebView 定时器运行”，该方案不依赖系统是否继续调度后台页面；相比“原生重写战斗逻辑”，复用现有 JavaScript 规则，范围和维护成本可控。

## 5. 后台运行架构

### 5.1 Android 前台服务

新增 `PokeIdleBackgroundService`（Java），职责仅限于：

- 以 Android 前台服务启动并显示常驻通知；
- 每隔固定心跳周期向 `MainActivity`/Capacitor bridge 发送“请求结算”的事件；
- 接收通知操作中的“停止挂机”命令并停止服务；
- 在 Android 13+ 请求通知权限，在 Android 14+ 声明正确的前台服务类型；
- 服务停止、应用关闭或用户明确关闭后台挂机时清理通知。

Manifest 增加前台服务和通知相关权限，服务使用 `START_NOT_STICKY`，避免用户主动停止后系统无限重启。服务不持有游戏数据，不直接修改存档。

### 5.2 Capacitor bridge 接口

`mobile/bridge-source.js` 暴露统一接口：

- `startBackgroundMode()`：申请通知权限（需要时）并启动服务；
- `stopBackgroundMode()`：停止服务并立即保存状态；
- `isBackgroundModeSupported()`：返回 Android/桌面环境能力；
- `onBackgroundTick(callback)`：接收服务心跳或前台恢复事件。

桌面端和浏览器提供空实现或返回“不支持”，不改变现有行为。bridge 只传递时间戳和控制命令，不传递完整存档对象。

### 5.3 时间戳结算模型

在运行时状态中增加后台挂机快照字段（不写入导出文件元数据）：

- `backgroundModeEnabled`：用户是否开启后台挂机；
- `backgroundStartedAt`：本次后台运行开始时间；
- `backgroundSettledAt`：最近一次成功结算的时间；
- `backgroundStats`：本次后台累计遇敌、捕获、逃跑和消耗球数量；
- `backgroundLastResult`：最近一条可展示的结果摘要。

进入后台时先保存当前游戏存档并记录 `backgroundSettledAt = Date.now()`。服务每次心跳或回到前台时调用 `settleBackground(now)`：

1. 计算 `elapsed = now - backgroundSettledAt`，限制单次最多结算 24 小时，防止设备时间异常或长期离线造成巨量循环。
2. 按与前台相同的遇敌间隔、增益和区域规则生成遭遇。
3. 对每个遭遇执行自动捕捉策略：选择启用且有库存的球，应用现有捕获率、逃跑率、闪光、变体、性别和个体值规则；无球时执行现有自动补球或逃跑逻辑。
4. 直接调用可复用的“结算并记录”函数，更新 `gameData`、图鉴、仓库、统计、系统日志和遭遇日志；不调用 `playCatchSequence()`、`showView()` 或任何 DOM 动画。
5. 将 `backgroundSettledAt` 推进到本次结算结束时间，保存存档；重复收到同一时间戳事件不得重复消耗道具或重复记账。

后台结算只在用户开启自动捕捉且没有手动暂停策略时执行自动抓捕；过滤器为“暂停”时保留遭遇摘要，回到前台后恢复为手动战斗页。用户关闭自动捕捉时，后台不自动扔球，但仍按现有规则记录遭遇是否超时逃跑。

### 5.4 前后台切换数据流

```text
前台开启后台挂机
  -> 保存存档与时间戳
  -> 启动 Android 前台服务
  -> 后台心跳触发 settleBackground(now)
  -> 更新游戏数据、日志、时间戳并保存
  -> 用户回到前台
  -> 停止/继续服务（取决于开关）
  -> 结算最后时间片
  -> 刷新统计、背包、道路和后台结果摘要
```

服务心跳失败不直接改数据；下一次前台恢复会根据 `backgroundSettledAt` 补算。应用进程被杀后重新启动，也从存档中的时间戳继续结算，保证结果可恢复。

## 6. 捕捉动画布局修复

### 6.1 样式生命周期

在 `src/animation.js` 中增加捕捉动画容器的布局快照/恢复辅助函数：

- `setupCatchAnim()` 修改容器前记录 `#encounterView` 和 `#catchStage` 的原始内联样式；
- `restoreCatchAnim()` 在所有成功、挣脱、异常和取消路径中清除动画写入的 `position/left/top/width/height`，并恢复快照中的其他内联样式；
- 球节点移回 `#catchStage` 后再清理其样式，确保 `.catch-stage .anim-ball` 的 CSS 定位重新生效；
- 恢复完成后强制一次布局读取，但不依赖延时。

恢复函数必须幂等：重复调用不会抛错，也不会把 CSS 默认值写成新的固定像素值。

### 6.2 舞台尺寸缓存

将 `getStageSize()` 的永久缓存改为按当前 `screenInner` 实际宽高和移动端布局版本失效：

- 宽高变化超过 1 px 时重新测量；
- `resize`、`visualViewport.resize` 和移动端动态高度更新后清除缓存；
- 无效尺寸继续使用现有最小尺寸和窗口尺寸回退；
- 桌面固定掌机比例的行为保持不变。

`fitPokemonImage()` 和捕捉动画使用同一次测量结果，避免图片尺寸与舞台尺寸来自不同坐标系。

## 7. 错误处理与边界

- 前台服务启动失败：保留前台游戏运行，提示“后台挂机不可用”，不修改自动捕捉设置。
- 通知权限被拒绝：不启动需要通知的前台服务，提示用户在系统设置中允许通知。
- 后台结算单次超过 24 小时：只结算最近 24 小时，并记录截断日志；后续前台恢复继续从新时间戳开始。
- 系统时间回拨：`elapsed <= 0` 时不结算，只把时间戳校正为当前时间。
- 存档写入失败：不推进 `backgroundSettledAt`，下次重试，避免结算结果与时间戳不一致。
- 后台结算过程中应用恢复前台：使用互斥锁，前台 Tick 等待结算完成，不重复处理同一时间片。
- 捕捉动画异常：`finally` 必须调用布局恢复；恢复失败只记录错误，不阻塞战斗收尾。

## 8. 测试策略

### 8.1 自动化测试

- 时间片结算：固定随机数和时间，验证遇敌数量、球消耗、捕获/逃跑结果、图鉴/仓库/日志更新。
- 幂等性：同一 `now` 重复结算不重复扣球、不重复增加统计。
- 时间边界：零时长、时间回拨、24 小时上限、无球、自动补球和过滤器暂停。
- 存档恢复：进程重启后从 `backgroundSettledAt` 继续结算，写入失败时保留旧时间戳。
- bridge/Android 契约：前台服务声明、通知操作、启动/停止接口和权限配置存在且名称一致。
- 捕捉布局：模拟动画前后的内联样式，验证 `encounterView`/`catchStage` 恢复；连续两次不同舞台尺寸运行，验证新尺寸生效；异常路径同样恢复。
- 现有 `npm run test:mobile` 与项目测试全部通过。

### 8.2 真机验收

- Android 8、Android 13/14 设备分别测试启动、停止、通知权限和后台心跳。
- 开启后台挂机后锁屏 5 分钟，解锁查看遇敌、捕获、逃跑、球库存和日志变化。
- 从后台切回、打开设置/仓库再回战斗，连续扔球，整页场景不偏移。
- 改变系统导航栏/安全区或触发 WebView resize 后再次扔球，舞台仍与文字框、主角和宝可梦对齐。
- 强制结束应用后重启，确认未重复结算且仍能继续后台时间片。

## 9. 发布边界

- 版本号递增一个 Android patch 版本，正式 release APK 继续使用现有签名配置。
- 发布说明明确“后台挂机会显示常驻通知并增加耗电”。
- 不修改导出存档格式；新增运行时后台字段需兼容旧存档，缺失时按关闭后台挂机处理。

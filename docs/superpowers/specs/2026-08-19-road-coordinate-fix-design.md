# 手机道路实体坐标修复设计

## 目标

修复 Android 手机模式下道路滚动物不可见的问题：

- 走路时生成的糖果、精灵球等道具没有显示在道路上。
- 普通遇敌、大量出没和时空扭曲宝可梦图标没有显示。
- 道路随从在不同手机比例下可能出现位置偏移。

修复后，所有道路实体都应在地图路面上出现，并沿现有滚动方向移动、碰撞或被主角拾取。

## 非目标

- 不修改道具掉落概率、糖果倍率、遇敌概率或事件规则。
- 不修改道路滚动速度、骑行规则、战斗触发条件和拾取奖励。
- 不改变桌面端的视觉布局和动画时序。
- 不调整地图素材、人物素材或道路 Canvas 的绘制内容。

## 现状与根因

Android 手机模式会对 `.console` 使用 CSS `transform: scale(...)`，以把固定的掌机设计尺寸适配到不同屏幕。道路实体目前在 `items.js`、`battle.js` 和 `events.js` 中通过以下方式计算位置：

1. 调用 `getBoundingClientRect()` 读取 `#screen`、主角和道路层的位置；
2. 直接把这些矩形的差值写入 `left/top` CSS 属性。

`getBoundingClientRect()` 返回的是经过祖先 CSS transform 放大后的物理坐标，而绝对定位的 `left/top` 需要未缩放的内部 CSS 坐标。手机缩放比例大于 `1` 时，道具和宝可梦的 `top` 被写到道路容器之外，随后被 `.screen` 的 `overflow: hidden` 裁剪，因此逻辑仍在运行但玩家看不到实体。

项目中的 `ui.js:getStageSize()` 已采用 `clientWidth/clientHeight` 避免同类问题，但道路实体尚未复用这一原则。

## 设计方案

### 1. 统一坐标辅助函数

在 `src/ui.js` 增加 `getScreenLayoutMetrics()`，以 `#screen` 为坐标原点：

- `width`、`height` 使用 `screen.clientWidth`、`screen.clientHeight`，不受 CSS transform 影响；
- 读取 `screen.getBoundingClientRect()` 只用于计算实际横向和纵向缩放比例；
- `rect(element)` 将元素的物理矩形按缩放比例还原为相对屏幕内部的 `left`、`top`、`width` 和 `height`；
- 屏幕或元素没有有效布局时返回 `null`，调用方等待下一帧或执行现有清理路径，禁止写入无效的零坐标；
- 桌面端没有缩放时比例为 `1`，保持现有坐标结果。

辅助函数不持有游戏状态，不修改 DOM，只提供一次布局快照和纯坐标换算结果。

### 2. 道路实体接入

以下模块改为使用同一份内部坐标快照：

- `src/items.js`：将道具初始位置、主角碰撞点和飞向主角的目标位置改为内部坐标；
- `src/battle.js`：将普通遇敌图标的初始位置、主角碰撞点和道路高度改为内部坐标；
- `src/events.js`：将大量出没和时空扭曲图标的初始位置、主角碰撞点和道路高度改为内部坐标；
- `src/follower.js`：将道路随从与主角的相对位置和视觉高度改为内部坐标。

动画帧仍按现有道路速度更新 `left`，碰撞阈值仍使用内部坐标，不改变奖励和战斗结算。

### 3. 生命周期与失效

每次实体生成或随从重新定位时读取一次坐标快照。视口 resize、移动端动态高度更新或页面切换后，下一次生成重新读取，不缓存跨布局周期的物理矩形。元素在视图隐藏时继续沿用现有隐藏/等待逻辑。

## 错误处理

- `#screen`、主角或道路层缺失：保持现有提前返回行为，不创建不可定位的实体。
- 元素布局尺寸为 `0`：不写入位置，等待下一帧；如果实体已存在且布局持续无效，沿用现有清理逻辑。
- 缩放比例无效或非正数：回退为 `1`，避免产生 `NaN` 或无穷坐标。
- 桌面端及 Android 未缩放场景：坐标换算结果与当前实现一致。

## 测试策略

新增道路坐标契约测试，使用静态源码检查和可测试的坐标换算输入覆盖：

1. 辅助函数使用 `clientWidth/clientHeight`，并按屏幕矩形缩放比例还原内部坐标；
2. 缩放比例为 `1` 时坐标保持不变；
3. 缩放比例大于 `1` 时，物理矩形差值会被正确除以缩放比例；
4. `items.js`、`battle.js`、`events.js` 和 `follower.js` 均调用统一辅助函数，不再直接把屏幕矩形差值写入道路实体位置；
5. `npm run test:mobile`、完整 Node.js 测试和 `node mobile/build-web.mjs` 全部通过。

Android release 构建后，从 APK 内的 Web 资源检查统一辅助函数和四个调用模块已被打包。

## 验收标准

- Android 手机走路时，糖果和精灵球图标从道路右侧进入并移动到主角处，拾取后正常入库。
- 普通遇敌、大量出没和时空扭曲宝可梦图标可见，并能正常碰撞进入战斗。
- 道路随从与人物脚底对齐，不因手机屏幕比例变化而偏移。
- 桌面端道路实体和现有掉落、遇敌、战斗流程无回归。
- release APK 通过 SHA-256、Android v2/v3 签名校验。
